## 언어 사이 연결

`기존 화면 → 기존 HTTP API → scripts/java-store.mjs → Java Main → 저장소 클래스 → 기존 파일`

Java 실행은 JSON 요청 한 개를 표준 입력으로 보내고 결과를 표준 출력으로 받는 방식입니다.
Java는 외부 HTTP 서버나 별도 포트를 열지 않습니다. 실패하면 앱 API 오류로 전달하며 JS 저장으로 대체하지 않습니다.
과제 규모에서 실행 구조를 쉽게 설명하기 위해 요청마다 JVM을 실행합니다. 작은 글 목록에 적합하며 대규모 서비스에서는 상주 프로세스로 바꿀 수 있습니다.
렌더링·AI·발행 검증 로직은 기존 JS를 공유해 화면과 발행 결과가 어긋나지 않게 합니다.

## Java 클래스 설계: 직접 작성 11개

| 클래스 | 책임 |
|---|---|
| Main | JSON 요청 해석, 작업 분배, 응답·오류 출력, 요청 간 파일 잠금 |
| AppException | 사용자에게 표시할 오류와 HTTP 상태 |
| JsonFiles | UTF-8 JSON/텍스트 읽기, 임시 파일 교체, 해시 |
| Workspace | 자료 폴더 설정, ID·실제 경로 검증, 이사한 자료의 경로 해석 |
| JobRepository | 글 생성·조회·메모/사진 순서/참고자료/메타데이터 저장 |
| SnapshotService | ready·입력 해시·스냅샷 생성·기존 CLI 상태 목록 |
| DraftRepository | 초안·검토 메모·분석·생성 지침 및 편집 이력 저장 |
| StorageService | 글 용량 계산, 안전한 글 전체 삭제 |
| CategoryService | 카테고리 검증과 블로그별 캐시 |
| PromptService | 카테고리 지침 CRUD·충돌 검사·적용 지침 결정 |
| StyleService | 기본 프롬프트·설정·이력·충돌 검사 |

JSON 파서는 공개 라이브러리 Gson을 사용합니다. 라이브러리 클래스는 직접 작성한 클래스 수에 포함하지 않습니다.

## 자료 격리와 호환

- 소스 폴더: `javaBlog/blog-automation-java`.
- 개발·웹 기본 자료: `%APPDATA%/H.Dev Studio Java Dev/workspace`.
- 배포 앱 자료: `%APPDATA%/H.Dev Studio Java/workspace`.
- 전용 재정의: `HDEV_JAVA_DATA_DIR`. 원본 앱의 `HDEV_DATA_DIR`는 이 앱에서 사용하지 않습니다.
- 기본 웹 포트: `4174`. Electron은 빈 포트를 선택합니다.
- `inbox`, `drafts`, `app.json`, `draft.json`, `manifest.json`, 카테고리·지침 JSON 형식 유지.
- 기존 자료는 사용자가 별도 폴더에 복사해 가져옵니다. 원본 자료를 자동으로 열거나 수정하지 않습니다.
- 저장 전 파일 경로와 사진 해시 확인, JSON 임시 파일 교체, 삭제 전 전체 대상 경로 확인.

## 검증 계획

1. 기존 전체 Node 테스트를 실제 Java 저장 경로에 연결한 상태로 실행.
2. Java 연결 실패, 기존 JSON 호환, 한글/이모지, 경로 이탈·링크·예약 이름, 자료 이사, 개별 글 삭제·다른 글 보존 검증.
3. 기존 Electron 발행·카테고리·프롬프트 검증을 모의 편집기와 임시 자료에서 실행.
4. Windows에서 Java 빌드, Electron 앱 시작, 독립 자료 폴더 확인.
5. 화면 파일 유지 및 Java 클래스 30개 이하 확인, 발표 문서·관계도·실행 안내 작성.

실제 AI 계정 사용량을 쓰는 생성과 티스토리 공개 발행은 자동 검증과 구분해 결과를 기록합니다.
