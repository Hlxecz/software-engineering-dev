# 4. 제약과 위험

[이전: 문맥과 이해관계자](03-시스템관계와이해관계자.md) · [목차](00-목차.md) · [다음: 규모와 시간 산정](05-규모와시간산정.md)

**단계 목적:** 실행·자료·검증의 한계를 확인하고 손실과 오작동을 줄이는 대응을 정한다.

## 지켜야 할 조건

| 제약 | 적용 기준 |
|---|---|
| 실행 환경 | Windows x64, 개발 Node 22 이상·JDK 17 이상; EXE 실행에도 Java 17 이상 필요 |
| 자료·호환 | 전용 자료/세션, UTF-8·기존 JSON/해시 유지; 원본 대신 복사본으로 검사 |
| 입력 | 수동 작성은 사진 0장 허용, AI 초안 생성은 사진 필요; PNG/JPEG/WebP 사진별 10 MiB·일반/표지 각각 최대 20장 |
| 지침·분류 | 현재 카테고리 캐시는 블로그 1개, 분류 지침은 블로그별 보존; 저장 버전·번호·전체 경로 확인 |
| 실행·저장 경계 | 저장 요청마다 Java를 실행하므로 대기 비용이 발생; Java 요청끼리 잠금, 지정 파일의 요청 실패 복원은 강제 종료·전원 장애 복구가 아님 |
| 확인한 범위 | 임시 자료·모의 AI/편집기·격리 EXE로 확인; 실제 AI 계정 호출·공개 발행·원격 기존 글 저장은 실행하지 않음 |

## 위험과 대응

| 위험·영향 | 대응 | WBS |
|---|---|---|
| 다른 창의 변경·부분 저장으로 초안/원문 불일치 | 기대 해시·저장 버전 재검사, 지정 파일 복원, 기존 불변 이력은 경로만 보호 | 2.2–2.3·5.2·6.3 |
| 원격 원문이 변경되어 덮어쓰기 충돌 | 제출 전 원문 재확인, 로컬 백업 후 명시적 재가져오기·합치기 | 6.2–6.4 |
| 제출 뒤 결과 미확인·중복 전송 | 제출 전 상태 기록, 불확실 상태 유지, 원격 결과 확인 전 자동 재시도 차단 | 6.1·6.4·8.2 |
| CLI·로그인·화면 구조·네트워크 변경 | 수동 로컬 흐름 유지, 오류 표시·작업 잠금 해제, 모의 회귀 | 4.2·6.1·8.2–8.3 |
| 삭제 중 OS 오류·일정 초과 | 삭제 전 전체 경로 검사·다른 글 보존, 부분 삭제 영향 안내; 위험 예비와 범위 재추정 | 3.4·8.1·9.1 |
