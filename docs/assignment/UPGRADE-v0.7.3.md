## 전체 기능과 언어 역할

기존 전체 기능 목록은 [PLAN.md](PLAN.md)의 표를 유지합니다. 아래 항목을 새 기반에 맞춰 추가·변경합니다.

| 기능 | JavaScript / Electron | Java |
|---|---|---|
| 첫 실행 | 예시 주소 차단, 웹 주소 설정, 설정 즉시 반영 | 기존 글·사진·초안 그대로 보관 |
| 계정 연결 | 티스토리 로그인 화면에서 소유 블로그 읽기, 단일 자동 연결·복수 선택 | 클래스 추가 없음 |
| 연결 상태 | 블로그 이름 버튼·사이드바, 로그인 확인·선택·취소 상태 표시 | 클래스 추가 없음 |
| 블로그 전환 | 공개 목록·발행 대상 변경, 진행 중 전환 차단, 주소 설정 파일 갱신 | 새 주소의 카테고리·지침 조회, 다른 블로그 데이터 보존 |
| 카테고리 읽기 | 글 관리의 보기 메뉴에서 읽기, 새 글 편집기 열지 않기 | 목록 정규화·검증·캐시 저장·불러오기 |
| 로컬 자료 | 기존 화면/API·렌더링·AI CLI·발행 연결 유지 | 글·초안·사진·버전·이력 저장/조회/삭제, 기본·분류별 프롬프트 관리 |

## 클래스와 폴더 구조

`bridge`, `common`, `workspace`, `post`, `category`, `prompt` 패키지의 기존 직접 작성 클래스 **11개**를 유지합니다. 관계도는 [ARCHITECTURE.md](ARCHITECTURE.md)에 있습니다. 새로운 계정 읽기는 `desktop/account.mjs`, 주소 설정은 `scripts/blog-settings.mjs`로 분리하며, Java 저장 기능은 기존 어댑터를 통해 실제 호출합니다.

사진 미리보기의 실제 파일 읽기도 `JobRepository.readImage`로 옮깁니다. Java가 경로를 검증하고 사진을 읽으면 Node는 브라우저에 바이트를 전달합니다. 원본·초안 사진의 HTTP 주소와 화면은 같습니다.

## 검증 계획

1. 원본 변경을 병합한 뒤 화면·AI·발행 코드가 v0.7.3과 일치하는지 비교합니다.
2. 기존 자동 검사와 실제 Java 통합 검사에서 JSON 호환·자료 격리·클래스 수·저장 경로를 확인합니다.
3. 블로그 전환 후 카테고리·프롬프트 분리 및 기존 자료 보존을 검증합니다.
4. Electron 모의 화면으로 발행·카테고리·프롬프트·첫 실행·계정 연결과 반응형 표시를 확인합니다.
5. Windows 개발 실행 및 새 버전 EXE의 Java 호출을 검증합니다. 실제 AI 생성이나 티스토리 공개 발행은 하지 않습니다.

## 반영 완료

**0.7.3-java.1 반영 및 검증 완료 — 2026-09-18.** 전체 자동 검사 86개(원본 79 + Java 7), Electron 발행·카테고리·프롬프트·첫 실행·계정 연결·말투 검사 6종을 통과했습니다. 실제 Windows 개발 앱과 새 portable EXE에서 Java 17.0.12의 사진·글·초안·지침 CRUD도 확인했습니다. 기존 JSON 형식, 11개 클래스, 기능별 패키지, 원격 연결 제거와 원본 자료 격리를 유지합니다.

전체 결과와 실행 파일 경로·체크섬은 [VERIFICATION.md](VERIFICATION.md)에 기록했습니다. 실제 AI 생성·공개 발행은 하지 않았습니다.
